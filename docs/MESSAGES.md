# Прототипы сообщений Gatecheck Bot — дизайн-спека

> **Статус:** спека v1.1 — РЕАЛИЗОВАНА в коде v0.10 (2026-09-20, §15 чек-лист закрыт).
> Дальнейшие правки текстов делаются ЗДЕСЬ и синхронно переносятся в код/тесты.
> **Источник требований:** фидбек первого боевого дня (Gulmorogod, 17 киллов на Amamake-гейте).

## 0. Общие правила оформления (действуют на все сообщения)

1. **HTML parse mode** (нужен для `<blockquote expandable>`); все данные экранируются.
2. **Все команды в текстах — с нижним подчёркиванием**: `/zone_status`, `/zone_on`, `/zone_off`,
   `/route_status`, `/route_stop`. Telegram делает их кликабельными ссылками; пробел внутри
   команды разрывает ссылку (причина замены). Старые формы с пробелом поддерживаются кодом
   для совместимости, но в текстах — только подчёркивания.
3. **Время в футерах — EVE Time (ET)** = UTC+0, формат `HH:MM`.
4. **Footer всех зональных репортов:**
   `Статистика за последний час. Запрос репорта по /zone_status. Местное время - HH:MM ET`
5. **Заголовок камп-репортов:** «Сейчас гайки кемпят в системе:» / «Сейчас гайки кемпят в системах:»
   (по числу систем с активностью). Единообразно для алертов, /zone_status и кнопки обновления.
6. **Блок системы = `<blockquote expandable>`** — свёрнут; до раскрытия видна только первая
   строка «В {система} N килов и {ISK} на гейтах» — по одному взгляду понятен масштаб боя.
7. **Десятиминутные киллы удалены полностью** (zK API отдаёт киллы с задержкой — 10-минутное
   окно всегда пустое). Все счётчики — **за последний час**. Триггеры D5:
   - накопление ≥ {hour} киллов на гейтах системы за час (дефолт 8, границы 4…20);
   - ценность: droppable ISK на гейтах системы за час ≥ {isk} (дефолт **0.5B**, границы 10M…5B).
8. Ссылки на zKillboard убраны (превью zK спамило чат). «Причина:» убрана — только конкретика.
9. **Анти-спам:** повторный репорт по системе — только при НОВЫХ киллах с прошлого репорта.
10. **Cooldown — только у зоны:** 15 мин на систему (настраивается). У дорожного монитора КД
    нет в принципе — алерты прилетают сразу же, как только появляются новые киллы.
11. **Разметка:** заголовки — жирный `<b>` (в прототипах `**…**`); последние строки (футеры,
    подсказки, ответы /settings) — курсив `<i>` (в прототипах `__…__`); копируемые списки
    (системы маршрута) — моноширинный `<pre>`-блок без ссылок и другой разметки внутри.
12. **Порядок блоков систем** — по убыванию суммарных киллов: самая горячая — первой.

## 1. Алерт зоны — одна система (пуш)

```text
**Сейчас гайки кемпят в системе:**

<blockquote expandable>Gulmorogod 21 килл и 1.2B ISK на гейтах

на Egmar: 4 за час (+4 за последние 10 минут), droppable 300M
атака: коллективный кемп · корабли: Caracal ×2, Maller, Capsule

на Amamake: 17 за час (+13 за последние 10 минут), droppable 900M
атака: соло · корабли: Tengu</blockquote>

__Статистика за последний час. Запрос репорта - по /zone_status. Местное время - 18:42 ET__
```

Правила блока системы:
- **Первая строка** (видна без раскрытия): `{система} {N} килл(ов) и {ISK} на гейтах`,
  где N — суммарные киллы на гейтах системы за час, ISK — сумма droppable за час по гейтам.
- **Каждый «горящий» гейт** (с киллами за час), через пустую строку:
  - `на {система-назначения}: {N} за час ({±N за последние 10 минут}), droppable {ISK}`;
    вместо `Stargate (Amamake)` — просто **«на Amamake»** (контекст гейта очевиден);
  - ниже — линия атаки: `атака: {соло | коллективный кемп | соло + групповые} · корабли: {список}`;
    состав атакующих — уникальные типы кораблей атакующих за час на гейте, «Имя ×N»;
  - гейты без киллов за час **не перечисляются** (не «горят»).
- **Дельта `({+N за последние 10 минут})`:** сколько киллов этого гейта произошло за последние
  10 минут (скользящее окно поверх часовой статистики — киллы с таймстампами уже загружены,
  отдельная таблица «прошлых репортов» не нужна). Новых киллов за 10 минут нет — дельта
  не выводится.
- **Плюрализация киллов:** 1 килл · 2–4 килла · 5+ киллов.
- NPC-киллы (zkb.npc) учитываются в счётчике, но не считаются атакой игроков — линия
  атаки для чисто-NPC гейта: `атака: NPC`.

## 3. /zone_status — с активной подпиской

То же самое (немедленный тик не выполняется — данные из накопленных событий; для свежести —
кнопка «🔄 Гейты: обновить»), плюс строка про чистые системы:

```text
**Сейчас гайки кемпят в системах:**

<blockquote expandable>…(блоки активных систем, как в §1)…</blockquote>

✅ Чисто: 10/13 систем
__Статистика за последний час. Запрос репорта по /zone_status. Местное время - 18:42 ET__
```

Если активных систем нет:

```text
**Сейчас гайки в зоне не кемпят.**

✅ Чисто: 13/13 систем
__Статистика за последний час. Запрос репорта по /zone_status. Местное время - 18:42 ET__
```

## 4. /zone_status — без подписки (разовый живой опрос)

Тот же формат (заголовок + блоки + footer), но данные — разовый опрос zK прямо сейчас,
после footer добавляется строка `Постоянное слежение: /zone_on`. Если чисто:

```text
**Сейчас гайки в зоне не кемпят.**

✅ Чисто: 13 систем
__Постоянное слежение: /zone_on__
```

## 5. Кнопка «🔄 Гейты: обновить» — отчёт по зонам

Немедленный тик зональных слежек чата (алерты по новым киллам придут как обычно), затем
**отчёт** — тот же формат §3 (заголовок «Сейчас гайки кемпят…», блоки, footer). Обновляет
**только мониторинг активных зон** (маршрут — отдельная сущность со своим статусом).

## 6. Старт маршрута: /route {A} {B}

Ответ на команду — ОДНО длинное сообщение, четыре части сверху вниз:
**вердикт → список систем → первый опрос → футер**. Только после отправки этого сообщения
включается алерт-цикл маршрута (КД нет — §0.10).

**1) Вердикт** — вычисляется по первому опросу, ставится в самое начало (после шапки
с маршрутом и TTL). Уровни от худшего к лучшему; выводится наивысшая достигнутая угроза:

| Уровень | Условие | Расшифровка |
|---|---|---|
| 🔴 маршрут очень опасен | килл на маршрутном гейте за час И там бомбы/бабблы | те же системы с примечаниями |
| 🟠 маршрут опасен | есть килл на маршрутном гейте за час | `(кемпы на маршрутных гейтах: X, Y)` |
| 🟡 безопасность под вопросом | киллы на гейтах систем маршрута за час, но НЕ на маршрутном гейте | `(X, Y — но не на маршрутных гейтах)` + примечания про бомбы/бабблы, если есть |
| 🟢 маршрут безопасен | все системы полностью чистые на гейтах | — |

**2) Список систем маршрута** — моноширинный `<pre>`-блок (§0.11): одна система на строку,
после названия через пробел — security-статус (формат как в игре: `1.0`, `0.5`, `-0.3`;
берётся из статики). Блок без ссылок и разметки: копируется целиком, вставляется в EVE
Notepad, каждая строка размечается ПКМ → Auto Link → Solar System.

**3) Первый опрос** — сразу при старте; горящие системы — блоки в том же формате, что у
/route_status (§8; приоритет маршрутных гейтов — §7). Чисто → «Сейчас гайки на маршруте
не кемпят.» + «Точек проверено: N.»

**4) Футер** — стандартный маршрутный (§0, курсив).

Прототип (показан случай 🟠):

```text
**🛡 Маршрут Amamake → Jita проложен: 16 систем, слежение на 60 мин активировано.**

🟠 **Маршрут опасен** (кемпы на маршрутных гейтах: Amamake, Auga).
(Не исключает бабблов по пути варпа внутри системы и внезапных атак, вердикт не абсолютен)

Список систем для копирования и разметки в утилиту Notepad:
`
Amamake 0.4
Auga 0.3
Siseide 0.3
…(все 16 систем, по одной на строку, sec через пробел)…
Jita 0.9
`
**Кемпы по пути:**

<blockquote expandable>**В Siseide между Auga и Palpalem** 3 килла на гейтах

🚩 на Palpalem: 2 за час (+2 за последние 10 минут)
атака: коллективный кемп · корабли: Sabre, Maller; признаки бабблов
на Auga: 1 за час (+1 за последние 10 минут)
атака: соло · корабли: Rifter</blockquote>

✅ Чисто: 14/16 систем
__Статистика за последний час. Остановить слежение: /route_stop. Местное время - 18:42 ET__
```

## 7. Алерт маршрута

Блок — в том же quote-формате (§0), пер-гейт, без «Stargate ()»:

```text
**🚨 Кемп на маршруте (точка 3/16):**

<blockquote expandable>**В Beta между Alpha и Gamma** 1 килл на гейтах

🚩 на Gamma: 1 за час (+1 за последние 10 минут)
атака: коллективный кемп · корабли: Maller 🫧 бабблы</blockquote>

🛡 Слежение маршрута Amamake → Jita — осталось 42 мин.
__Статистика за последний час. Остановить слежение: /route_stop. Местное время - 19:05 ET__
```
Правила маршрутного блока:
- **Первая строка:** `**В {система} между {предыдущая} и {следующая}** {N} килл(ов) на гейтах`
  — «между X и Y» = соседние системы по маршруту. ISK не показывается: сумма выпавшего
  на маршруте не имеет смысла.
- **Порядок гейтов:** сначала 🚩-маршрутные (ведут в ±1 систему по маршруту — их нужно видеть
  в первую очередь), остальные — в хвосте по остаточному принципу (вторичный приоритет).
- **Строка гейта:** `🚩 на {назначение}: {N} за час ({+M за последние 10 минут})` — динамика
  кемпа, без droppable.
- **Линия атаки:** как в §1 (тип кемпа обязателен: соло/коллективный/смешанный · корабли)
  + отдельные пометки об опасности:
  - `💣 смартбомбы` — weapon_type_id атакующих входит в SDE-группу Smart Bomb (group 55).
    Типичные кемповые модули (в основном фракционные/офицерские Large/Mega ради максимального
    радиуса поражения): Imperial Navy Large EMP Smartbomb (17926), Republic Fleet Large Proton
    Smartbomb (17938), Caldari Navy Large Shrapnel Smartbomb (17930), Shadow Serpentis Large
    Thermal Smartbomb (28211). Если weapon_type_id атакующего — ID смартбомбы, урон наносился
    смартбомбой.
  - `🫧 бабблы` — потенциальное/подтверждённое заграждение:
    1. **Корабли атакующих** (главный маркер, сопоставление по ship_type_id в attackers):
       дикторы Sabre (22456), Flycatcher (22464), Eris (22444), Heretic (22460); HIC Devoter
       (11993), Onyx (11999), Phobos (12015), Broadsword (12011).
    2. **Подтверждение запуска** — по weapon_type_id атакующих: Interdiction Sphere Launcher
       (11584) у дикторов, Warp Disruption Field Generator (16279) у HIC (корабль мог держать
       цель обычным поинтом — без подтверждения пометка «потенциально»).
- **Триггер пуша:** новые киллы на 🚩-маршрутных гейтах → алерт сразу (КД нет). Киллы на прочих
  гейтах систем маршрута пуша не дают — меняют вердикт на 🟡 и видны в /route_status.

Прототип выше; «(точка 3/16)» — позиция горящей системы в маршруте, «между Alpha и Gamma» —
соседние системы по маршруту.

## 9. /start

```text
Привет, {имя}! 👋

Gatecheck Bot v0.10.0 — слежение за гейт-кампами EVE Online для дальнобойщиков и сальважеров. Вдохновлен небезызвестным [сервисом](https://eve-gatecheck.space/) и адаптирован под специфические нужды.

Основные команды:
• /zone_on — включить мониторинг зоны «Hed + соседи» для сальважа (алерты по гейтам)
• /zone_status — разовый отчёт по гейтам зоны сальважа
• /route Amamake Jita — проложить маршрут + начать слежение (TTL 1 ч)
• /help — вся справка

Подписок и доната нет, но если бот понравился - "спасибо" любыми исками на ник `Grastanideus` :-)
```

\`Grastanideus\` — моноширинный ник (HTML: `<code>Grastanideus</code>`), в ТГ копируется
одним тапом по тексту.

## 10. /help

```text
**Команды:**
/zone_on — включить зону «Hed + соседи в радиусе одной системы» · /zone_off — выключить
/zone_status — одноразовый отчёт по гейтам зоны, актуальный по активным кемпам 
/route {A} {B} — кратчайший маршрут между произвольными системами + частый мониторинг систем по дороге (на протяжении часа, либо до отмены) 
/route_status — апрос статуса горящих систем по дороге (если в алерты не верится)
/route_stop — остановить мониторинг (рекомендуется по окончании рейса: не нагружайте бота)
/settings — пороги алертов 

Кнопки: 🔄 Гейты: обновить · 🛡 Зона вкл/выкл · 🚀 Маршрут · ⚙️ Пороги.
Все отчёты — только по киллам на гейтах, не далее чем за последний час.
Версия: v0.10.0, [Гитхаб-репозиторий](https://github.com/sstarostin1/Gatecheck_bot).
```

## 11. /settings — пороги D5

Просмотр (`/settings`):

```text
**Пороги зоны (D5), границы:**
• hour: 8 киллов на гейтах за час (пределы 4…20)
• isk: 0.5B droppable на гейтах за час (пределы 10M…5B)
• cooldown: 15 мин (пределы 5…60 мин) — только для зоны
• атака в алертах: вкл - сообщение о составе и виде кемпа

__Изменить: /settings_hour 10 · /settings_isk 0.7B · /settings_cooldown 20м · /settings_attackers off__
__Сброс всех: /settings_reset__
```

Изменение (`/settings_hour 10`, `/settings_isk 0.7B`, `/settings_cooldown 20м`,
`/settings_attackers off`) — ответ `✅ hour = 10 (действует со следующего /zone_on)`.
Границы: hour 4…20 · isk 10M…5B · cooldown 5…60 мин · attackers on/off.
КД зоны и маршрута раздельны: cooldown применяется ТОЛЬКО к зональным репортам; у дорожного
монитора КД нет в принципе — алерты прилетают сразу же, как только появляются новые киллы
на маршруте.

## 12. /ping — только админ

Админ — текущий ответ (аптайм, статика, слежки, счётчики zK).
**Не-админ — бот молчит** (служебная команда, пользователям не нужна).

## 13. Кнопки

**Reply-клавиатура** (под полем ввода, задаётся на /start и /help):

```text
[ 🔄 Гейты: обновить ]
[ 🛡 Зона: вкл ]   [ 🛡 Зона: выкл ]
[ 🚀 Маршрут: статус ]   [ 🚀 Маршрут: стоп ]
[ ⚙️ Пороги ]
```

- «🔄 Гейты: обновить» — немедленный тик зональных слежек + отчёт §3 (обновляет ТОЛЬКО зоны);
  без зональных слежек — разовый опрос (§4).
- Кнопки «Зона: статус» нет — функционал полностью покрыт «Гейты: обновить».
- Labels человекочитаемы; обработка — по точному тексту кнопки (F.text == label).

**Inline:** «🔄 Обновить» — только на зональных репортах (§1–§4; callback refresh:zone).
На сообщениях маршрута inline-кнопок нет.

## 14. Ошибки и краевые случаи (тексты)

```text
Не нашёл систему: {name}. Проверь написание (граф — весь Новый Эден, без вормхолов).
Маршрут {A} → {B} не найден (нет гейт-связности).
Один маршрут уже активен — останови мониторинг предыдущего и создай новый.
Граф гейтов ещё не собран: python scripts/fetch_static.py
Слежение не активно. /route {A} {B} — включить.
Зона не включена. /zone_on — включить.
```

## 15. Что нужно для реализации (чек-лист v0.10)

1. **HTML parse mode**: `DefaultBotProperties(parse_mode=ParseMode.HTML)`; экранирование всех
   данных; `<b>` — заголовки (§0.11), `<i>` — футеры/подсказки, `<pre>` — список систем
   маршрута (§6), `<blockquote expandable>` — блоки систем.
